# 设计卡：消息链路与富媒体管道（dsh-lark-bridge）

> 状态：现行设计 · 2026-08-23 建档
> 覆盖：入站归一化 → agent 驱动 → 出站渲染（cot/审批卡/文件/图片）全链路。

## 1. 入站链路

```
LarkChannel WS (dedup/chatQueue/mention 策略内置)
  ▼ NormalizedMessage
bridge.ts handleMessage()
  ├─ authorization.ts —— 发信人白名单/admin 判定（admin_from + allowFrom）
  ├─ session.ts —— chatId→sessionId 路由（p2p/group 各自 scope）
  └─ images.ts / files.ts —— 入站图片收集（HostImageRef），随 HostUserMessage 注入
```

设计约束：
- **mention 门控**（`requireMention: true`）：群里只有被 @ 才响应；p2p 全收。白名单收紧用 senderAllowlist。
- **消息归一化**是桥的边界职责——上游 SDK 的原始事件不进 agent 层。

## 2. Agent 驱动与回复收集

```
composeChatAgent() → agent.followup(userMsg)
  ▼ 事件流（host session events）
assistant/chunk ──► text-chunks      → 正文流式卡片更新
reasoning-chunks ─► cot.ts           → 思考过程卡（模型无 reasoning 自然退化，功能不删）
tool-call-chunks ─► ToolPresentation → 工具活动卡 + 审批卡（approvalCard/settledCard）
turn/end(error) ──► notices.ts       → 错误卡（如 PI_AI_ERROR 上游故障透传）
```

- **审批卡**：`approvalActionValue()` 解析按钮回调 → `HostApprovalOutcome` 四态（allowed-once/rejected/cancelled/unavailable）；2 分钟未处理自动提醒（approvalReminderMs）。
- **goal 恢复**：`autoResumeGoals: true` —— dsh 的 activation 是进程内存态，重启即 disarmed；开启后聊天再说话时桥自动 re-arm，部署不再静默杀死进行中的任务。

## 3. 出站富媒体

| 能力 | 实现 | 关键坑 |
|---|---|---|
| 本地文件发送 | `outbound.allowedFileDirs` 配置 | Config schema 漏字段会被 Loader **静默丢弃**→ `@larksuite/channel` 默认拒绝本地文件（防读 ~/.ssh）。三处同步：Config 接口+zod schema+resolveConfig 透传，runtime.ts 里挂 `options.outbound` |
| 图片发送 | images.ts 收集 HostImageRef | 上游 image-management 重构（EXIF 归一化/maxImageDimension）全是可选字段，桥零改动兼容 |
| 思考卡 | cot.ts | `output: cot` + `showProcess: true`；无 reasoning 的模型自动退化为纯答案 |

## 4. 会话持久化（session-persistence-jsonl）

- 路径 `<dsh-home>/sessions/<workdir-scope>/feishu-oc_*/session.jsonl.zstd`（本机在 `~/.dsh/sessions/`）
- **zstd 多帧拼接**：每帧独立可解，magic `\x28\xb5\x2f\xfd` 分隔；第一帧必须恰好一行 header（assertZstdHeaderFrame）
- chunk 行展开为 `seq0+k` 多事件（texts/args 字段）；seq 断裂 = 双实例并发写入实锤
- 修复工具：技能 scripts/scan_dsh_log.py（定位）+ fix_session_zstd.py（保帧重建，禁止整文件单帧重压/明文回写）

## 5. token 压力预警（tokenPressure）

每 10 分钟轮询 host tokenMeter，活跃会话总 token ≥ 阈值（默认 120k）→ 飞书提醒 /compact；**每次跨越只提醒一次**，降回自动重臂。配置于 cordis.patch.yml feishu-channel config。
