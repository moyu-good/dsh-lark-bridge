# 设计卡：截断预算（`limits`）可配置

> 状态：现行设计 · 2026-10-30 建档 · CHENJIAMIAN

## 1. 目的与非目标

**目的**：桥发往飞书的每处截断都变成**部署可调的预算**，默认值放大到「当工作台用」够用，同时保留上限，别让一张卡被一万行日志撑成一面墙。

**起因**（2026-10-30 真机反馈）：「我看好多东西都被截断了」。逐处排查后确认：**回答正文一个字都不截**，被截的全是过程可见性与摘要类通知；而当时的默认值是按「扫一眼就走的聊天」调的——工具结果 3 行 / 240 字、每个参数 120 字、后台任务尾部 700 字。这些恰好砍掉「为什么失败」的那几行。

**非目标**：

- 不动平台硬限制（单条 CoT 事件 4096 字符），只保证插话预算留在它下面。
- 不截断回答正文、不截断文件/图片（维持现状）。
- 不改任何渲染形态（哪些东西进思考区、哪些进聊天）。

## 2. 架构与数据流

新增配置段 `limits`，在 `resolveConfig` 里解析成 `ResolvedConfig.limits`，再沿既有路径下发：

```
cordis.patch.yml  limits.*
  → Config schema / resolveConfig → DEFAULT_LIMITS 补缺
  → installBridge: createCotRenderer({ limits })
      ├─ summariseResult(text, toolResultLines, toolResultChars)
      ├─ summariseArguments(json, toolArgChars)
      └─ userChatMessageText(data, userMessageChars)
  → installBridge: quotedPrefix(quoted, quoteChars)
  → installBridge: jobDoneLine(terminal, jobTailChars)
  → installBridge: boundCardText(command, approvalArgChars)   （审批卡）
  → commands: runSkillsCommand(line, skills, limits)           （/skills 预览）
```

## 3. 契约设计

| 配置键 | 默认 | 作用 |
|---|---|---|
| `limits.toolResultLines` | 10 | 思考区里一个工具结果显示的行数（原 3） |
| `limits.toolResultChars` | 1600 | 上述结果的字符上限（原 240） |
| `limits.toolArgChars` | 400 | 每个保留参数值的字符上限（原 120） |
| `limits.userMessageChars` | 3000 | 插话进思考区的字符上限（原 1200），须 < 4096 |
| `limits.quoteChars` | 6000 | 引用正文进入模型输入的字符上限（原 1200） |
| `limits.jobTailChars` | 2500 | 后台任务完成通知保留的尾部（原 700） |
| `limits.approvalArgChars` | 1000 | 审批卡上工具参数的字符上限（原 600） |
| `limits.skillPreviewChars` | 2000 | `/skills <name>` 预览的字符上限（原 800） |

每个渲染函数都保留「不传就用 `DEFAULT_LIMITS`」的签名，老的直接调用方（含测试）不受影响。

## 4. 失败路径

| 失败 | 处理 |
|---|---|
| 部署没写 `limits` | 全部取默认值，行为与配置后的新默认一致 |
| 只写了一部分键 | 其余键取默认值（`resolveLimits` 逐项补缺） |
| 配了 `userMessageChars` > 4096 | 单事件仍会被平台的 4096 上限截成 `truncated: true`；文档写明「须 < 4096」 |
| 配成 0 或负数 | schema 用 `z.number().min(1)` 拒绝，启动期即报错，不进运行时 |
| 想彻底不截断 | 把对应预算调得很大；但平台侧 4096 上限与卡片载荷仍会兜底 |

## 5. 测试

- **mock 单测**：`tests/limits.spec.ts` 7 条——默认值解析、单项覆盖、`resolveConfig` 贯通、默认值比旧写死值宽且插话预算 < 4096、三条渲染路径（参数摘要 / 任务尾部 / 引用）按调用方预算生效。
- **既有断言调整**：`notices.spec.ts`（尾部测试改用 4000 字输入 + 新增自定义预算用例）、`quote.spec.ts`（长引用改用 20000 字输入 + 自定义预算）、`plugin.spec.ts`（审批卡上限 600 → 1000）。
- **smoke-live**：重启后观察工具结果预览与失败输出是否足够定位问题。
