# 设计卡制度（design cards）

> 铁则：**凡开发，先建档；实现完，回填记录；阻塞了，也留档。**
> 本目录是 dsh-lark-bridge 的全部现行设计与调查档案。

## 为什么

- 功能设计只活在会话里就会丢；落在 `docs/design/` 才能被下一个贡献者（人或 bot）接续。
- 调查后不可行的结论同样有价值——记录「为什么不做/被什么阻塞」，避免重复踩坑。

## 卡片模板骨架

```markdown
# 设计卡：<功能名>（dsh-lark-bridge）

> 状态：现行设计 / 🚧 调查中 / 🚧 阻塞于上游 / ⛔ 归档无需求 · YYYY-MM-DD 建档 · 作者

## 1. 目的与非目标
## 2. 架构与数据流（或可行性调查记录）
## 3. 契约设计 / 实现预案
## 4. 失败路径（每条防线要有真实事故背书）
## 5. 测试三层（mock 单测 → plugin-contract 43 项 → smoke-live 真链路）
## 6. 变更记录（追加式，不删改历史行）
```
