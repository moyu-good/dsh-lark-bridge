# dsh-lark-bridge 开发经验（2026-08-20 沉淀）

> 整理自 P008 完美插件开发过程中踩过的坑与验证过的方法。
> 适用范围：本仓库开发、Windows + pnpm + vitest 环境、dsh 生态插件开发。

## 一、环境与工具链（Windows）

### 1. node_modules junction 损坏
- **症状**：tsc 报 `Cannot find type definition file for 'node'`、vitest/pnpm 卡死、pnpm install 报 `EACCES lstat qrcode-terminal`。
- **根因**：pnpm 重建 node_modules 中途被中断，`.pnpm` 下的真实包还在，但顶层 junction（typescript / vitest / tsdown / qrcode-terminal / @types/node）全部变成坏链接。
- **修复**：`cmd /c rmdir <坏junction>` 后重新 `New-Item -ItemType Junction` 指回 `.pnpm/<pkg>/node_modules/<pkg>`。
- **预防**：pnpm install 必须跑到结束；中途杀掉进程会留下坏链接。修完先 `cmd /c dir @types\node` 验证。

### 2. 单次 shell 调用有 ~12s 超时
- 长命令（pnpm install、完整 vitest）会超时被杀，**不要前台硬跑**。
- 正确姿势：`Start-Process cmd /c "..." -WindowStyle Hidden -PassThru`，输出重定向到 log，然后分批轮询 `Get-Process -Id` + `Get-Content log -Tail`（每次 sleep ≤8s，避免再次超时）。

### 3. Node 版本
- 仓库要求 `node ^22.19 || >=24`，本机 22.16 只产生 warning，不影响安装/测试。

### 4. vitest 4 的 reporter
- `--reporter=basic` 不存在（会被当成自定义模块加载失败），用默认或 `--reporter=default`。

### 5. 不要用 `npx tsc`
- 会把 `tsc@2.0.4` 错误包装进来。用仓库内真实编译器：
  `node node_modules/.pnpm/typescript@6.0.3/node_modules/typescript/bin/tsc -p tsconfig.json --pretty false`

## 二、PowerShell 写 Python 脚本的转义

- **双引号 here-string（@"..."@）里反引号是 PowerShell 转义符**，写 backtick 必须双写，写 Python 字符串里的转义极容易变成 `\a`（BEL 字符）或错误转义。
- **推荐：Python 脚本一律用单引号 here-string（@'...'@）**，内容是字面量，再在 Python 里用 raw string（前缀 r），backtick/反斜杠都安全。
- Python 字符串里 `\a` 是 BEL（0x07），不是“反斜杠+a”，写文件路径/注释要小心。
- 文本替换脚本要验证每个 replace 是否命中（`if old not in t: raise`），避免“看似成功实则没改”。

## 三、dsh 契约对齐方法论

### 1. 先读上游源码，再写窄拷贝
- 桥不 import 上游包，靠 `src/host.ts` 结构拷贝；**载荷形状必须以 deepseek-harness 源码为准，不能猜**。
- 实测教训：第一版把 `agent/status` 载荷猜成 `{agentId, status}`，实际是 `{agent: Agent, status}`；`skills/change` 无载荷；`workflow/log|phase` 是双参数 Cordis 事件 `(info, text)`，不是 session event。
- **dsh 默认分支是 `master`，不是 `main`**（raw 拉取地址要用 master）。

### 2. 事件分两类，作用域不同
- **durable session events**（`session/event` 载荷）：`todo/write`、`goal/change`、`tool-workflow/*`、`compaction/*`、`schedule/change`、`subagent/descriptor` —— 通过 `ctx.on('session/event', ...)` + type guard 消费。
- **live Cordis events**：`agent/*`、`subagent/start|end`（`Scoped<Agent>/Scoped<SubagentRuntime>`，注册在 agentCtx 才收到）、`workflow/*`（全局，双参数）、`skills/change`（无载荷）。
- 新事件类型通过 `declare module '@deepseek-ai/cordis'` 增强 Events，桥才 typecheck 通过。

### 3. 契约漂移门禁
- `scripts/verify-dsh-contract.mjs`：fetch `raw.githubusercontent.com/deepseek-ai/deepseek-harness/master/...` 关键文件，正则校验 host.ts 镜像的关键签名，漂移即 exit 1。
- GitHub Actions（`.github/workflows/ci.yml`）：contract-test → typecheck → drift → vitest。

### 4. inject 保持最小
- `inject: ['agents', 'goals']` 是硬依赖；可选服务一律 `ctx.get(...)` 降级（settings/loader/commands/sessionPersistence/agentPresets/workspaceRegistry/sessionQuery/jobs）。

## 四、dsh 架构关键认知

- Everything is a plugin + Cordis；profile/bundle/patch 分层叠加，无特权内核。
- ~62 个 capability seams、22 个 tool package；桥只消费与 IM 交互相关的子集。
- **“全部官方功能在飞书可用”不是好目标**：编辑器/LSP/PTY/代码调试/设置页属于官方 Web UI。飞书桥应做“适合 IM 的官方功能深度原生呈现 + 通知/审批/断点续跑”，不适合的给一句话入口。
- 飞书桥差异化三张牌：全生命周期可视、断点续跑（autoResumeGoals）、决策留痕（审批卡 + /audit）。

## 五、测试方法论

- **Windows 路径**：不要用 `lastIndexOf('/')` 切路径，用 `node:path` 的 `dirname/join`。
- **harness 模式**（tests/harness.ts）：
  - fake agents 的 `compose` 用**独立的 `new Context()`**，测试服务要在 agentCtx 上 `provide`（例：jobs 必须 `createFakeAgents({ jobs })` 传进 agentCtx，只 provide 到根 ctx 拿不到）。
  - 集成断言用 `vi.waitFor(() => expect(harness.fake.sent.some(...)).toBe(true))`。
  - 测实时事件：先发 durable 建立映射（如 `tool-workflow/run-start` 建立 runId→chat），再 emit 对应 live 事件。
- **质量门禁**：改完先跑 tsc（直接二进制）→ plugin-contract-test.mjs → 全量 vitest；全绿才提交。当前基线：258 tests / 41 contract checks / drift green。

### 1. dsh-feishu-chat 部署运维（hermes 8/16）
- 桥是**独立 dsh 进程内的 feishu-channel 插件**，Hermes 只做启动器；不要把它当成 Hermes 的附属模块改。
- **重启铁律**：`systemctl restart dsh-feishu-chat`；禁用 `safe-restart.sh` 和手动拉起——双实例会并发写坏会话 log。
- **斜杠面板缺权限**：线上曾缺 `application:app_slash_command`，补权限后要发一条消息触发注册，否则 `/` 列表是空的。
- **会话文件修复**（log 被写坏时）：截断到最后一条完整的 `turn/end`，保持 zstd 帧结构（首帧是单行 header），不要随意删中间帧。
- **排障顺序**：先数进程（确认不是双实例），再查 log，不要犟“后台没反应”。

### 2. 通道与模型纪律（hermes 8/19-8/20）
- opencode 通道已全删 + watchdog 禁用，规则备份在 `/path/to/user/rules-backup\`；`opencode-go` 远程 API 网关不受影响；**codex 桥勿动**。
- 主模型 `deepseek-v4-flash/max`，识图走 `muse-spark-1.2`（codex_responses）；deepseek 档位一律 max，muse 用 xhigh，**只确认不改，改了会出错**。
- 自启动：Hermes gateway + dsh 已配 systemd enabled + Startup vbs；机器重启后不要手动重复拉起。
- Windows/WSL 互通：cmd stdout 为空 ≠ Windows 卡死，用 9p 文件探针判活。

### 3. 云鹊桥生态调研（P006，兵部）
